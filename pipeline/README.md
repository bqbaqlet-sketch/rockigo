# Глава → курс в RockiGo

Одна команда читает страницы из выданного Markdown и проверяет их диапазон по PDF, собирает учебный слой и таблицу покрытия, валидирует четыре файла по схемам организаторов, затем собирает из проверенного слоя автономный HTML. В `chapters.json` заданы границы глав, названия шагов, краткие учебные заметки и два разбираемых случая из источников. Эти заметки отделены от дословных цитат.

## Запуск

Нужны Python 3.11+, Node.js 24, две пары Markdown/PDF и оригинальные схемы из папки `пакет_вводных/01_схемы`. Файлы и результаты хранятся в локальных папках `source/` и `output/`.

```sh
python -m pip install -r pipeline/requirements.txt
python pipeline/build_course.py latyshova
python pipeline/build_course.py vendelshtein-rezvanov
```

Сборка трёх обучающих глав с видео и общей стартовой страницей:

```sh
python pipeline/build_training.py --ffmpeg ffmpeg --voice pwsh.exe
```

Рендеру нужны FFmpeg с libx264, PowerShell и установленный Windows-голос Microsoft Irina Desktop. Из пакета организаторов добавьте `passport.schema.json` в `source/official/`, а пары PDF и Markdown для Басниева и Кузнецова положите в `source/` по именам из `chapters.json`. Откройте `output/training/index.html` в браузере. Передавайте всю папку, чтобы рядом с курсами сохранились MP4, паспорта и спецификации. По завершении проверки у ментора отметьте её фактический результат в паспортe.

Имена входных файлов и границы страниц заданы в `chapters.json`. Схемы `node`, `coverage`, `routing` и `task` лежат в `source/official/`. Для следующей главы передайте файл с описанием через `--manifest`. Поля `steps` и `decision` можно опустить. В этом случае скрипт соберёт черновик из извлечённых фрагментов внутри каждого диапазона страниц. Для русскоязычных глав он подбирает отрывки и термины, а учебные выводы и практикум на данных можно добавить в описании главы.

## Результаты

- `RockiGo.html` открывается с диска. Внутри путь, карточки, задания, разборы и печатный конспект.
- `layer.json`, `routing.json` и `task.json` содержат граф, выбор форматов и задания.
- `coverage.csv` и `coverage.json` показывают, к какому узлу привязана каждая выделенная единица и где нужна сверка.
- `review.csv` содержит только строки, которые нужно сверить по PDF.
- `verification.json` содержит охват, число проверенных цитат и заданий, контрольные суммы и время сборки.

Цитаты и числа сверяются с организаторским Markdown. Проверка схемы контролирует структуру. В `needs_review` остаются единицы для предметной сверки со сканами, включая рисунки, таблицы, формулы, примеры и повреждённое распознавание.
